# บทที่ 4: การควบคุมทิศทางและลูป

## ทบทวน

บทที่แล้วเราคำนวณยอดรวมและส่วนลดด้วยตัวดำเนินการ แล้วเก็บผลไว้ในตัวแปร

แต่โค้ดที่รันตรง ๆ จากบนลงล่างยังตอบโจทย์ข้อมูลจริงไม่ได้ เพราะตารางหนึ่งมีหลายแถว และแต่ละแถวต้องถูกตัดสินต่างกัน

บทนี้จะให้โค้ดเลือกทางเดินเอง ด้วยเงื่อนไข (condition) และลูป (loop)

## if คือการเลือกทำตามเงื่อนไข

`if` คือคำสั่งที่บอกว่า ถ้าเงื่อนไขเป็นจริงให้ทำบล็อกข้างใน

เงื่อนไขคืออะไรก็ได้ที่ให้ค่าจริงเท็จ เช่น การถามว่ายอดถึงหนึ่งพันบาทหรือยัง

ทำไมต้องใช้ในงานทำความสะอาดข้อมูล เพราะกฎของข้อมูลมักมาในรูปเงื่อนไข เช่น ยอดถึงหนึ่งพันส่งฟรี หรือช่องว่างให้ถือว่าไม่มีค่า

```python
def shipping_fee(total: float) -> float:
    if total >= 1000:
        return 0.0
    return 50.0


for total in [450.0, 1000.0, 2500.0]:
    print(f"ยอด {total:.2f} ค่าส่ง {shipping_fee(total):.2f} บาท")
```

ผลลัพธ์

```txt
ยอด 450.00 ค่าส่ง 50.00 บาท
ยอด 1000.00 ค่าส่ง 0.00 บาท
ยอด 2500.00 ค่าส่ง 0.00 บาท
```

ยอด 450 ไม่ถึงเกณฑ์จึงได้ค่าส่ง 50 ส่วนยอด 1000 พอดีเกณฑ์ก็ได้ 0 เพราะเราใช้ `>=` ไม่ใช่ `>`

ย่อหน้าหลัง `if` ต้องเยื้องเข้ามาสี่ช่อง หรือหนึ่งแท็บ การเยื้องคือโครงสร้างของภาษา ไม่ใช่เรื่องความสวยงาม ถ้าเยื้องผิด Python จะโยน `IndentationError` ทันที

## if กับ elif เมื่อมีหลายช่วง

`elif` คือการเพิ่มเงื่อนไขอีกชั้น ใช้เมื่อผลลัพธ์มีมากกว่าสองแบบ

```python
def classify_amount(total: float) -> str:
    if total < 500:
        return "small"
    elif total < 2000:
        return "medium"
    else:
        return "large"


for amount in [120.0, 500.0, 2000.0]:
    print(f"{amount:.2f} อยู่ในกลุ่ม {classify_amount(amount)}")
```

ผลลัพธ์

```txt
120.00 อยู่ในกลุ่ม small
500.00 อยู่ในกลุ่ม medium
2000.00 อยู่ในกลุ่ม large
```

ลำดับสำคัญมาก Python ตรวจจากบนลงล่างแล้วหยุดที่เงื่อนไขแรกที่จริง

เพราะเงื่อนไขแรกคือ `total < 500` ค่า 499.99 จึงได้ `small` และค่า 500 จึงตกไปถึงเงื่อนไขที่สอง ถ้าสลับลำดับเป็นตรวจ `total < 2000` ก่อน ค่า 120 จะได้ `medium` ทันที

จุดนี้สำคัญกับงานทำความสะอาดข้อมูล เพราะการแบ่งกลุ่มยอดเงินต้องกำหนดขอบให้ชัดว่าตัวเลขที่พอดีขอบอยู่กลุ่มไหน

## หลายเงื่อนไขด้วย and กับ or

เงื่อนไขเดียวอาจไม่พอ เราต่อหลายเงื่อนไขด้วย `and` และ `or`

`and` จริงเมื่อทั้งสองข้างจริง `or` จริงเมื่อข้างใดข้างหนึ่งจริง

งานทำความสะอาดข้อมูลใช้สองตัวนี้ตลอด เพราะกฎของข้อมูลจริงมักมีเงื่อนไขซ้อน เช่นต้องเป็นออเดอร์ที่ค้างชำระและยอดสูงพอจะถูกส่งให้คนตรวจ

```python
def needs_review(status: str, total: float) -> bool:
    return status == "pending" and total >= 2000


def is_suspicious(status: str) -> bool:
    return status == "" or status == "unknown"


rows = [
    {"status": "pending", "total": 2600.0},
    {"status": "pending", "total": 450.0},
    {"status": "paid", "total": 4200.0},
]

for row in rows:
    status = row["status"]
    total = row["total"]
    print(f"{status} ยอด {total:.2f} ต้องตรวจหรือไม่ {needs_review(status, total)}")

print(is_suspicious(""))
print(is_suspicious("unknown"))
print(is_suspicious("paid"))
```

ผลลัพธ์

```txt
pending ยอด 2600.00 ต้องตรวจหรือไม่ True
pending ยอด 450.00 ต้องตรวจหรือไม่ False
paid ยอด 4200.00 ต้องตรวจหรือไม่ False
True
True
False
```

แถวแรกเข้าเงื่อนไขทั้งสองข้างจึงได้จริง แถวที่สองสถานะตรงแต่ยอดไม่ถึงจึงได้เท็จ ส่วนแถวที่สามสถานะไม่ตรงตั้งแต่ต้น

`or` ต่างออกไป มันจริงเมื่อข้างใดข้างหนึ่งจริง ข้อความว่างกับคำว่า `unknown` จึงผ่านทั้งคู่

## ตรวจว่าค่าอยู่ในกลุ่ม

เมื่อต้องเทียบกับหลายค่าที่เป็นไปได้ ใช้ `in` กับกลุ่มค่าแทนการเขียน `or` หลายรอบ

งานทำความสะอาดข้อมูลใช้วิธีนี้กับคำสะกดที่ต่างกันของค่าเดียวกัน ซึ่งเจอบ่อยในคอลัมน์สถานะและประเทศ

```python
def describe_status(status: str) -> str:
    if status == "paid":
        return "ชำระแล้ว"
    if status in {"cancelled", "canceled"}:
        return "ยกเลิก"
    if status == "":
        return "ไม่ระบุ"
    return "รอดำเนินการ"


for status in ["paid", "cancelled", "canceled", "", "pending"]:
    print(f"{status!r} แปลว่า {describe_status(status)}")
```

ผลลัพธ์

```txt
'paid' แปลว่า ชำระแล้ว
'cancelled' แปลว่า ยกเลิก
'canceled' แปลว่า ยกเลิก
'' แปลว่า ไม่ระบุ
'pending' แปลว่า รอดำเนินการ
```

สองคำสะกดที่ต่างกันให้ผลเหมือนกัน เพราะเราระบุทั้งคู่ไว้ในกลุ่ม

สังเกตว่าเราใช้ `if` สามอันติดกันโดยไม่มี `elif` เพราะแต่ละอัน `return` ออกไปแล้ว ถ้าเงื่อนไขไหนจริงฟังก์ชันก็จบ ไม่ต้องตรวจอันที่เหลือ

## ค่าจริงเท็จ

ใน Python ทุกค่าใช้เป็นเงื่อนไขได้ ค่าที่ถือว่าเท็จมีไม่กี่อย่าง คือ `0`, `0.0`, `""`, `[]`, `{}`, `None` และ `False` ที่เหลือถือว่าจริงทั้งหมด

```python
for value in [0, -1, "", "0", [], None]:
    print(f"{value!r} เป็นจริงหรือไม่ {bool(value)}")
```

ผลลัพธ์

```txt
0 เป็นจริงหรือไม่ False
-1 เป็นจริงหรือไม่ True
'' เป็นจริงหรือไม่ False
'0' เป็นจริงหรือไม่ True
[] เป็นจริงหรือไม่ False
None เป็นจริงหรือไม่ False
```

กับดักที่เจอบ่อยในงานข้อมูลคือ `"0"` ซึ่งเป็นข้อความ ไม่ใช่ตัวเลข มันจึงเป็นจริง เพราะข้อความที่มีตัวอักษรถือว่าไม่ว่าง

แปลว่าถ้าเราเขียนเงื่อนไขสั้น ๆ กับค่าที่อ่านมาจาก CSV ข้อความ `"0"` จะผ่านเงื่อนไข ทั้งที่จำนวนเป็นศูนย์ ทางที่ปลอดภัยคือแปลงเป็นตัวเลขก่อนแล้วค่อยตรวจ

## ตรวจ None กับข้อความว่าง

ช่องที่ไม่มีข้อมูลจาก CSV จะมาเป็นข้อความว่าง `""` ส่วนช่องที่ไม่มีค่าในโค้ดเราจะใช้ `None`

สองอย่างนี้ไม่เหมือนกัน และต้องตรวจด้วยวิธีต่างกัน

```python
email = None

print(email is None)
print(email == "")
```

ผลลัพธ์

```txt
True
False
```

ใช้ `is None` เมื่อถามว่าไม่มีค่าเลย และใช้ `== ""` เมื่อถามว่าข้อความว่างหรือไม่

งานทำความสะอาดข้อมูลต้องแยกสองกรณีนี้ให้ออก เพราะบางครั้งเราอยากเติมค่าตั้งต้นเฉพาะช่องที่ว่าง แต่ปล่อยช่องที่เป็น `None` ไว้ให้ตรวจต่อ

## for วนผ่านสมาชิก

`for` คือลูปที่วนผ่านสมาชิกทีละตัวตามลำดับ

ทำไมต้องใช้ เพราะตารางหนึ่งมีหลายแถว และเราต้องทำอย่างเดียวกันกับทุกแถว

```python
ORDERS = [
    {"order_id": "O0001", "status": "paid", "total": 4200.0},
    {"order_id": "O0002", "status": "pending", "total": 1150.0},
    {"order_id": "O0003", "status": "paid", "total": 450.0},
    {"order_id": "O0004", "status": "cancelled", "total": 2600.0},
    {"order_id": "O0005", "status": "paid", "total": 300.0},
]

for row in ORDERS:
    print(row["total"])
```

ผลลัพธ์

```txt
4200.0
1150.0
450.0
2600.0
300.0
```

ชื่อ `row` เป็นเพียงชื่อชั่วคราวที่ใช้เรียกสมาชิกตัวปัจจุบัน ตั้งเป็นอะไรก็ได้ แต่ควรสื่อความหมาย เราใช้ `row` เพราะสมาชิกแต่ละตัวคือหนึ่งแถวของตาราง

## enumerate เมื่อต้องรู้ลำดับ

บางครั้งนอกจากค่าของสมาชิก เราต้องรู้ด้วยว่ามันเป็นตัวที่เท่าไร

`enumerate` ให้สองค่าออกมาพร้อมกัน คือลำดับกับสมาชิก

```python
for position, row in enumerate(ORDERS, start=1):
    print(f"แถวที่ {position} คือ {row['order_id']}")
```

ผลลัพธ์

```txt
แถวที่ 1 คือ O0001
แถวที่ 2 คือ O0002
แถวที่ 3 คือ O0003
แถวที่ 4 คือ O0004
แถวที่ 5 คือ O0005
```

ค่า `start=1` ทำให้ลำดับเริ่มที่หนึ่ง ซึ่งตรงกับภาษาที่คนอ่านรายงานเข้าใจ ถ้าไม่ใส่ ลำดับจะเริ่มที่ศูนย์เหมือนการนับของ Python

งานทำความสะอาดข้อมูลใช้ค่านี้เพื่อรายงานว่าแถวไหนมีปัญหา เช่นแถวที่ 37 มีอีเมลผิดรูปแบบ

## ตัวสะสม

รูปแบบที่ใช้บ่อยที่สุดของลูปคือการสะสมค่าไว้ในตัวแปร แล้วอ่านค่าหลังลูปจบ

งานทำความสะอาดข้อมูลใช้รูปแบบนี้เพื่อหายอดรวม จำนวนแถวที่ผ่านเงื่อนไข และค่าสูงสุดของคอลัมน์

```python
def total_revenue(rows: list[dict]) -> float:
    total = 0.0
    for row in rows:
        total += row["total"]
    return total


print(f"ยอดรวมทั้งหมด {total_revenue(ORDERS):.2f} บาท")
```

ผลลัพธ์

```txt
ยอดรวมทั้งหมด 8700.00 บาท
```

จุดสำคัญคือต้องสร้างตัวสะสมไว้นอกลูป ถ้าประกาศ `total` ไว้ในลูป ค่าจะถูกรีเซ็ตทุกรอบและได้เพียงค่าแถวสุดท้าย

## นับด้วยดิกชันนารี

การนับจำนวนแถวแยกตามหมวดหมู่ทำได้ด้วยดิกชันนารี (dictionary) ที่เก็บคู่ระหว่างค่ากับจำนวน

งานทำความสะอาดข้อมูลใช้การนับเพื่อดูว่าค่าไหนโผล่บ่อยผิดปกติ ซึ่งมักเป็นสัญญาณของปัญหาการป้อนข้อมูล

```python
def count_by_status(rows: list[dict]) -> dict[str, int]:
    counts: dict[str, int] = {}
    for row in rows:
        status = row["status"]
        counts[status] = counts.get(status, 0) + 1
    return counts


for status, count in count_by_status(ORDERS).items():
    print(f"{status} มี {count} รายการ")
```

ผลลัพธ์

```txt
paid มี 3 รายการ
pending มี 1 รายการ
cancelled มี 1 รายการ
```

`counts.get(status, 0)` แปลว่าขอดูค่าของคีย์นี้ ถ้ายังไม่มีให้ใช้ศูนย์แทน แล้วบวกหนึ่งเก็บกลับไป

ถ้าเขียนบวกตรง ๆ โดยไม่ใช้ `get` จะพังตอนเจอสถานะครั้งแรก เพราะคีย์นั้นยังไม่มีในดิกชันนารี

## break เมื่อเจอสิ่งที่ต้องการแล้ว

`break` สั่งให้ออกจากลูปทันที

งานทำความสะอาดข้อมูลใช้ `break` เมื่อต้องการแค่ตัวอย่างแรกของปัญหา ไม่ต้องสแกนทั้งตาราง

```python
for row in ORDERS:
    if row["status"] == "cancelled":
        print(f"เจอรายการยกเลิกที่ {row['order_id']} จึงหยุด")
        break
```

ผลลัพธ์

```txt
เจอรายการยกเลิกที่ O0004 จึงหยุด
```

งานทำความสะอาดข้อมูลใช้ `break` เมื่อต้องการแค่ตัวอย่างแรกของปัญหา ไม่ต้องสแกนทั้งตาราง

ข้อควรระวังคือ `break` ออกได้แค่ลูปชั้นในสุดที่มันอยู่ ถ้ามีลูปซ้อนกันสองชั้น การออกจากชั้นในไม่ทำให้ชั้นนอกหยุด

## continue เมื่อข้ามรอบนี้

`continue` สั่งให้ข้ามส่วนที่เหลือของรอบนี้ แล้วไปรอบถัดไป

งานทำความสะอาดข้อมูลใช้ `continue` เพื่อกรองแถวที่ไม่ต้องสนใจออกก่อน แล้วค่อยทำงานกับแถวที่เหลือ

```python
def paid_ids(rows: list[dict]) -> list[str]:
    result: list[str] = []
    for row in rows:
        if row["status"] != "paid":
            continue
        result.append(row["order_id"])
    return result


print(paid_ids(ORDERS))
```

ผลลัพธ์

```txt
['O0001', 'O0003', 'O0005']
```

สองบรรทัดนี้ให้ผลเหมือนการเขียน `if` ครอบทั้งบล็อก แต่แบบ `continue` อ่านง่ายกว่าเมื่อมีเงื่อนไขกรองหลายชั้น

## while เมื่อไม่รู้จำนวนรอบล่วงหน้า

`while` วนตราบใดที่เงื่อนไขยังจริง

ต่างจาก `for` ตรงที่ `for` รู้ว่ามีกี่สมาชิก แต่ `while` ใช้เมื่อจำนวนรอบขึ้นกับสถานะระหว่างทาง

งานทำความสะอาดข้อมูลใช้ `while` เมื่อต้องลองซ้ำจนกว่าข้อมูลจะผ่านเกณฑ์ เช่นลองอ่านไฟล์ใหม่เมื่อไฟล์ยังเขียนไม่เสร็จ

```python
remaining = 3

while remaining > 0:
    print(f"เหลืออีก {remaining} แถว")
    remaining -= 1
```

ผลลัพธ์

```txt
เหลืออีก 3 แถว
เหลืออีก 2 แถว
เหลืออีก 1 แถว
```

ต้องมีอะไรสักอย่างในลูปที่ทำให้เงื่อนไขค่อย ๆ เป็นเท็จ ในที่นี้คือการลดค่าลงทีละหนึ่ง

ถ้าลืมบรรทัดนั้น เงื่อนไขจะจริงตลอดและโปรแกรมค้างไม่จบ เรียกว่าลูปอนันต์ (infinite loop) ต้องกด Ctrl+C เพื่อหยุด

## return ในลูป

ฟังก์ชันที่ค้นหาค่าแล้ว `return` จะออกจากฟังก์ชันทันที ไม่ต้องรอให้ลูปจบ

งานทำความสะอาดข้อมูลใช้วิธีนี้เพื่อหยิบแถวแรกที่ตรงเงื่อนไข เช่นแถวแรกที่ยอดเกินเกณฑ์ หรือแถวแรกที่วันที่ผิดรูปแบบ

```python
def find_first_large(rows: list[dict]) -> dict | None:
    for row in rows:
        if row["total"] >= 2000:
            return row
    return None


print(find_first_large(ORDERS))
print(find_first_large([{"total": 100}]))
```

ผลลัพธ์

```txt
{'order_id': 'O0001', 'status': 'paid', 'total': 4200.0}
None
```

`return None` ที่อยู่หลังลูปจะทำงานเฉพาะเมื่อลูปจบโดยไม่เจออะไรเลย ตรงนี้คือเหตุผลที่ต้องวางไว้ในระดับเดียวกับ `for` ไม่ใช่ในบล็อกของ `if`

## สรุป

| ต้องการ | ใช้ |
|---|---|
| เลือกทำเมื่อเงื่อนไขจริง | `if` กับ `else` |
| เลือกจากหลายช่วง | `if`, `elif`, `else` |
| รวมเงื่อนไข | `and` กับ `or` |
| ตรวจว่าอยู่ในกลุ่มค่า | `in` |
| ตรวจว่าไม่มีค่า | `value is None` |
| ตรวจว่าข้อความว่าง | `value == ""` |
| วนทุกสมาชิก | `for row in rows` |
| วนพร้อมลำดับ | `enumerate(rows, start=1)` |
| รวมยอด | ตัวสะสมนอกลูป |
| นับแยกหมวด | `counts.get(key, 0) + 1` |
| หยุดเมื่อเจอ | `break` |
| ข้ามรอบนี้ | `continue` |
| วนจนกว่าเงื่อนไขจะเท็จ | `while` |
| คืนค่าแรกที่เจอ | `return` ในลูป |

สามข้อที่ต้องจำ

1. เงื่อนไขตรวจจากบนลงล่างแล้วหยุดที่อันแรกที่จริง ลำดับจึงเปลี่ยนผลลัพธ์ได้
2. `"0"` เป็นข้อความจึงเป็นจริง ต้องแปลงเป็นตัวเลขก่อนตรวจ
3. ตัวสะสมต้องประกาศนอกลูป ไม่อย่างนั้นค่าจะถูกรีเซ็ตทุกรอบ

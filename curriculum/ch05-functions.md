# บทที่ 5: ฟังก์ชัน

## ทบทวน

บทที่แล้วเราใช้ `if` เลือกทางเดิน และใช้ลูปวนทุกแถวของตาราง

โค้ดที่ได้ทำงานถูก แต่พอลองใช้ซ้ำในอีกที่หนึ่งเราต้องคัดลอกทั้งบล็อกมาวางใหม่ ซึ่งจะกลายเป็นปัญหาเมื่อต้องแก้ทีหลัง

บทนี้จะห่อโค้ดเหล่านั้นเป็นฟังก์ชัน (function) ที่เรียกใช้ซ้ำได้ด้วยชื่อเดียว

## ฟังก์ชันคือบล็อกโค้ดที่ตั้งชื่อไว้

ฟังก์ชันคือกลุ่มคำสั่งที่เราตั้งชื่อ แล้วเรียกใช้เมื่อไรก็ได้

เราสร้างด้วยคำว่า `def` ตามด้วยชื่อ วงเล็บ และเครื่องหมายทวิภาค (colon) ปิดหัว

ทำไมต้องใช้ในงานทำความสะอาดข้อมูล เพราะการทำความสะอาดคือชุดกฎเดิมที่ต้องใช้กับทุกไฟล์ที่เข้ามา การห่อกฎไว้เป็นฟังก์ชันทำให้แก้ที่เดียวแล้วมีผลทุกที่

```python
def clean_text(value: str | None) -> str:
    if value is None:
        return ""
    return " ".join(value.split())


print(f"ชื่อที่สะอาดแล้วคือ {clean_text('  Somchai   Jaidee ')!r}")
print(f"ค่าจาก None คือ {clean_text(None)!r}")
```

ผลลัพธ์

```txt
ชื่อที่สะอาดแล้วคือ 'Somchai Jaidee'
ค่าจาก None คือ ''
```

แบบที่พิมพ์ด้วย `!r` จะเห็นเครื่องหมายคำพูดครอบ แบบนี้ทำให้แยกออกได้ว่าค่าที่ได้เป็นข้อความ ไม่ใช่ `None`

ชื่อ `value` ในวงเล็บคือพารามิเตอร์ (parameter) เป็นช่องรับค่าที่ผู้เรียกส่งเข้ามา ส่วน `-> str` คือการบอกชนิดของค่าที่จะคืน

`value.split()` ตัดข้อความตามช่องว่างทุกชนิดและทิ้งช่องว่างที่ติดกันออก เหลือเป็นรายการคำ ส่วน `" ".join(...)` เอารายการนั้นมาต่อกลับด้วยช่องว่างเดี่ยว

## พารามิเตอร์กับอาร์กิวเมนต์

พารามิเตอร์คือชื่อช่องในนิยามฟังก์ชัน ส่วนอาร์กิวเมนต์ (argument) คือค่าจริงที่ส่งเข้ามาตอนเรียก

```python
def format_amount(value: float, currency: str = "บาท", decimals: int = 2) -> str:
    return f"{value:,.{decimals}f} {currency}"


print(format_amount(1150))
print(format_amount(1150, currency="USD"))
print(format_amount(1150, decimals=0))
```

ผลลัพธ์

```txt
1,150.00 บาท
1,150.00 USD
1,150 บาท
```

การส่งค่าตามลำดับเรียกว่าอาร์กิวเมนต์เชิงตำแหน่ง (positional argument) ส่วนการระบุชื่อพารามิเตอร์กำกับเรียกว่าอาร์กิวเมนต์เชิงชื่อ (keyword argument)

แบบหลังอ่านง่ายกว่าเมื่อฟังก์ชันมีพารามิเตอร์หลายตัว เพราะคนอ่านไม่ต้องนับลำดับเอง

## return กับการพิมพ์ต่างกัน

`return` ส่งค่ากลับออกจากฟังก์ชันให้ผู้เรียกเอาไปใช้ต่อ ส่วน `print` แสดงผลออกจอแล้วจบแค่นั้น

```python
def add_vat_printed(total: float) -> None:
    print(total * 1.07)


def add_vat(total: float) -> float:
    return total * 1.07


add_vat_printed(1000)
print(add_vat(1000))
print(add_vat(1000) + 500)
```

ผลลัพธ์

```txt
1070.0
1070.0
1570.0
```

แบบแรกพิมพ์ 1070 ออกมาแล้วค่าหายไป เอาไปบวกต่อไม่ได้

แบบที่สองคืนค่ากลับมา จึงเอาไปบวก 500 ได้เป็น 1570

งานทำความสะอาดข้อมูลต้องใช้แบบคืนค่า เพราะผลลัพธ์ของฟังก์ชันหนึ่งจะถูกส่งเข้าไปเป็นข้อมูลของอีกฟังก์ชันหนึ่ง

## parse_price แปลงราคาที่สกปรก

ราคาในข้อมูลจริงมาในหลายรูปแบบ ทั้งมีสัญลักษณ์บาท มีจุลภาคคั่นหลักพัน หรือมีจุดทศนิยม

`parse_price` รวมการจัดการทั้งหมดไว้ที่เดียว

```python
def parse_price(value: str | None) -> float | None:
    if value is None:
        return None

    cleaned = value.replace("฿", "").replace(",", "").replace(" ", "")
    if not cleaned:
        return None

    body = cleaned.lstrip("+-")
    if body.count(".") > 1 or not body.replace(".", "", 1).isdecimal():
        return None

    return float(cleaned)


for raw in ["฿1,150", "300.00", "", "abc"]:
    print(f"{raw!r} กลายเป็น {parse_price(raw)!r}")
```

ผลลัพธ์

```txt
'฿1,150' กลายเป็น 1150.0
'300.00' กลายเป็น 300.0
'' กลายเป็น None
'abc' กลายเป็น None
```

อ่านทีละช่วง

- บรรทัดแรกตัดสัญลักษณ์บาท จุลภาค และช่องว่างออก
- ถ้าเหลือแต่ข้อความว่างให้คืน `None` ทันที
- ขั้นถัดไปตัดเครื่องหมายบวกหรือลบออกก่อน แล้วนับจุดทศนิยม ถ้ามีจุดเกินหนึ่งจุดหรือมีตัวอักษรปนอยู่ ให้คืน `None`
- ถ้าผ่านทุกข้อจึงแปลงเป็นจำนวนจริง

เราเลือกคืน `None` แทนการปล่อยให้โปรแกรมพัง เพราะในไปป์ไลน์จริงเราไม่ต้องการให้แถวเดียวที่มีปัญหาระเบิดทั้งงาน

## safe_int กับค่าเริ่มต้น

`safe_int` แปลงค่าเป็นจำนวนเต็ม ถ้าแปลงไม่ได้ให้คืนค่าเริ่มต้นที่เรากำหนด

```python
def safe_int(value: str | int | None, default: int = 0) -> int:
    if isinstance(value, int):
        return value
    if isinstance(value, str) and value.strip().lstrip("+-").isdecimal():
        return int(value)
    return default


print(safe_int("12"))
print(safe_int("x", -1))
print(safe_int(None))
```

ผลลัพธ์

```txt
12
-1
0
```

`isinstance(value, int)` ตรวจว่าค่าเป็นจำนวนเต็มอยู่แล้วหรือไม่ ถ้าใช่ก็คืนไปเลย

กรณีข้อความ เราตัดช่องว่างและเครื่องหมายบวกลบออกก่อน แล้วถามว่าที่เหลือเป็นเลขล้วนหรือไม่ ถ้าใช่จึงแปลง

งานทำความสะอาดข้อมูลใช้ฟังก์ชันแบบนี้กับคอลัมน์จำนวนที่ปนข้อความแปลก ๆ และต้องการให้งานเดินต่อได้โดยไม่หยุด

## ฟังก์ชันเรียกฟังก์ชันอื่นได้

ฟังก์ชันหนึ่งเรียกฟังก์ชันอื่นได้ และนี่คือวิธีที่เราใช้ฟังก์ชันเล็ก ๆ ต่อกันเป็นงานใหญ่

```python
def clean_row(row: dict) -> dict:
    return {
        "name": clean_text(row.get("name")),
        "price": parse_price(row.get("price")),
    }


rows = [
    {"name": "  Nattapong   Sri ", "price": "฿4,200"},
    {"name": None, "price": ""},
]

for row in rows:
    print(clean_row(row))
```

ผลลัพธ์

```txt
{'name': 'Nattapong Sri', 'price': 4200.0}
{'name': '', 'price': None}
```

บล็อกนี้ใช้ `clean_text` กับ `parse_price` จากหัวข้อก่อนหน้า

`clean_row` ไม่ได้ทำความสะอาดเองเลย มันแค่เรียกสองฟังก์ชันที่ทำหน้าที่นั้นแล้วประกอบผลกลับเป็นดิกชันนารี

ผลคือถ้าวันหนึ่งเราต้องแก้วิธีทำความสะอาดชื่อ เราแก้ที่ `clean_text` ที่เดียว ไม่ต้องตามแก้ทุกที่ที่ใช้

## ขอบเขตของตัวแปร

ตัวแปรที่ประกาศในฟังก์ชันอยู่ได้แค่ในฟังก์ชันนั้น เรียกว่าขอบเขต (scope)

```python
message = "ข้อความจากภายนอก"


def demo_scope() -> str:
    message = "ข้อความในฟังก์ชัน"
    return message


print(demo_scope())
print(message)
```

ผลลัพธ์

```txt
ข้อความในฟังก์ชัน
ข้อความจากภายนอก
```

ตัวแปร `message` ในฟังก์ชันเป็นคนละตัวกับตัวแปรนอกฟังก์ชัน แม้ชื่อจะเหมือนกัน

การเขียนค่าลงตัวแปรนอกฟังก์ชันจากในฟังก์ชันต้องประกาศ `global` ซึ่งเราจะหลีกเลี่ยง เพราะทำให้โค้ดตามยาก ทางที่ดีคือรับค่าเข้ามาทางพารามิเตอร์และคืนค่าออกมาทาง `return`

## ค่าเริ่มต้นที่แก้ได้เป็นกับดัก

ค่าเริ่มต้นของพารามิเตอร์ถูกสร้างครั้งเดียวตอนนิยามฟังก์ชัน ไม่ได้สร้างใหม่ทุกครั้งที่เรียก

ถ้าค่าเริ่มต้นเป็นลิสต์หรือดิกชันนารี มันจะถูกใช้ร่วมกันทุกครั้ง

```python
def append_note_bad(notes: list[str] = []) -> list[str]:  # noqa: B006
    notes.append("ตรวจแล้ว")
    return notes


print(append_note_bad())
print(append_note_bad())
```

ผลลัพธ์

```txt
['ตรวจแล้ว']
['ตรวจแล้ว', 'ตรวจแล้ว']
```

ครั้งที่สองมีคำว่า `ตรวจแล้ว` สองคำ ทั้งที่เราติดไว้ครั้งเดียว เพราะลิสต์ตัวเดิมถูกใช้ซ้ำ

เครื่องหมาย `# noqa: B006` ท้ายบรรทัดมีไว้บอกตัวตรวจโค้ด (linter) ว่าเราตั้งใจเขียนแบบนี้เพื่อสาธิต อย่าเพิ่งเตือน ในโค้ดจริงไม่ควรเขียนแบบนี้เลย

วิธีแก้คือใช้ `None` เป็นค่าเริ่มต้น แล้วสร้างลิสต์ใหม่ข้างใน

```python
def append_note(notes: list[str] | None = None) -> list[str]:
    result = [] if notes is None else notes
    result.append("ตรวจแล้ว")
    return result


print(append_note())
print(append_note())
```

ผลลัพธ์

```txt
['ตรวจแล้ว']
['ตรวจแล้ว']
```

แบบนี้แต่ละครั้งที่เรียกโดยไม่ส่งค่า จะได้ลิสต์ใหม่เสมอ

กับดักนี้สำคัญกับงานข้อมูลเพราะฟังก์ชันที่รับรายการผลลัพธ์เข้ามาสะสม มักถูกเรียกซ้ำหลายรอบในลูปเดียว

## สรุป

| ต้องการ | ใช้ |
|---|---|
| นิยามฟังก์ชัน | `def name(param: type) -> type` |
| รับค่าตอนเรียก | พารามิเตอร์ในวงเล็บ |
| ส่งค่ากลับ | `return` |
| ค่าเริ่มต้น | `param: type = value` |
| ส่งด้วยชื่อ | `name(param=value)` |
| ตรวจชนิด | `isinstance(value, int)` |
| ค่าเริ่มต้นที่ปลอดภัย | `None` แล้วสร้างใหม่ข้างใน |
| เรียกฟังก์ชันอื่น | เรียกตามชื่อในบล็อก |

สามข้อที่ต้องจำ

1. ฟังก์ชันที่ทำงานข้อมูลต้อง `return` ไม่ใช่ `print`
2. ค่าเริ่มต้นที่เป็นลิสต์หรือดิกชันนารีใช้ร่วมกันทุกครั้ง ให้ใช้ `None` แทน
3. ตัวแปรในฟังก์ชันไม่รั่วออกไปข้างนอก
